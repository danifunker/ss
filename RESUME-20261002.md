## Gotchas learned this session

- **Session 6:** the simulation's DDR model delivers the beats of a burst
  back to back and the board's port does not under load; a suite that
  passes in simulation and on an idle board can still hide a fill race:
  run the suite with `--ddr-gaps` too. NetBSD's `ps -e` prints the
  environment, not every process: `stresswatch.sh`'s "alive" line there
  only proves the shell answers (Main's disk reads show the loops run).
  The board stress scripts (`solstress.sh`, `nbstress.sh`) leave the OSD at
  `console=serial` and HD0 at the last image.

- **Self-matching kills, once more:** `pkill -f 'scratch/shot[.]sh'` in a
  command line that also runs `scratch/shot.sh` kills that very shell.
  Never `pkill -f`/`pgrep -f` a pattern your own command contains; a
  `pgrep -f` wait loop whose pattern matches itself never ends.
- `scripts/setopt.sh` with no argument writes **all defaults** (console
  back to video): always pass `console=serial`.
- `kbtype.sh` cannot type `?` (no Shift): set `input-device ttya` (and
  `output-device ttya`) at the screen's `ok`, `reset`, then type the rest
  on ttya. Keys typed during the OBP's memory test get partly lost (the
  tail of a sequence can still land: one run set only `input-device`).
- The SS20 OBP with a blank NVRAM sets `diag-switch?` true (bad checksum);
  the diag boot's memory test takes ~3 minutes; the normal boot ~15 s.
- mrext's REST keyboard has no modifiers (websocket key-down/up has).
- Solaris 8's `mdb`: no CTF, no `::msgbuf`, `::vtop` for kernel addresses
  only; `::ps`, `::cpuinfo`, `addr::walk seg | ::seg`, `addr,n/X`,
  `addr::dis` work. `p_as` is the second word of `proc_t`. Force a dump of
  a hung Solaris with `pcdump -c 0 -j 0` (CPU 0 resumes at 0: a text
  fault, a panic, a dump).
- A hung NetBSD did not answer `pcdump` at all (no "cpus" line): use
  `timeout` around it, and check Main's disk reads
  (`/proc/$(pidof MiSTer)/io`) to tell a wedged core from a busy one.
- One `hwtest.sh 20 cpu` right after a deploy captured nothing (log of one
  byte); the rerun passed. Unexplained.
