## Gotchas learned this session

- **Self-matching kills, again:** a command line that contains
  `console.sh` (or any `pkill -f`/`pgrep -f` pattern's literal match)
  anywhere, even in a later part of the same `bash -c`, gets its own
  shell killed by a `pgrep -f 'console[.]sh' | kill` in an earlier part.
  Stop and start captures only through `scratch/stopcap.sh` and
  `scratch/startcap.sh`, in commands that never spell the script's name.
- The OBP's diag mode prints POST and probe output on ttya, then moves
  the console to the screen; `setenv output-device ttya` + `reset` keeps
  it on ttya through Solaris (then the console is scriptable).
- Solaris's kernel addresses are deterministic per image and machine:
  `unix` text at `0xf0040000` (its ELF addresses, `llvm-nm` works
  directly), the `TI,TMS390Z55` module text at `0xf0161820`.
- The real SS20 PROM does not run under QEMU 11.1.1 (Data Access Error at
  POST); QEMU's OpenBIOS on `-M SS-20` boots disk images (use
  `-nographic`, or OpenBIOS puts its console on the TCX) but not the
  Solaris CD.
- In QEMU, Solaris's `sd` instances for a new controller path come after
  the old ones in `path_to_inst` (7-13 here); the block device is major
  32, minor instance × 8 + slice.
- The board's D-cache runs write-through (`dcache mode: write-through`, the
  OSD WB option off): write-back paths are only exercised by atomics and
  explicit flushes.
- Earlier sessions' gotchas still hold (LLVM 13-bit immediates, VIVT SS5
  D-cache, Verilator run times, two readers on `/dev/ttyS1`, OpenBIOS
  dropping keys while printing, `pcdump` needs ttya to itself).
